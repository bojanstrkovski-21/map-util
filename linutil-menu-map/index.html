    Adding, changing or removing an entry

    Summarized from the repository's SPEC.md and AGENTS.md.

    1. Script. Put it under core/tabs/<tab>/. Use POSIX sh (#!/bin/sh -e), source common-script.sh with the right number of .., and call checkEnv before relying on PACKAGER, ESCALATION_TOOL, ARCH or DTYPE.
    2. Menu entry. Add or edit it in that tab's tab_data.toml: name, description, exactly one of script, command or entries, plus task_list, preconditions and multi_select as needed. A submenu is an entry with entries.
    3. New top-level tab. A new directory with its own tab_data.toml, plus a line in core/tabs/tabs.toml. The order there is the tab order.
    4. Remove. Delete the entry from tab_data.toml and its script if nothing else uses it.
    5. Afterwards. Run cargo xtask docgen when entries or descriptions changed, cargo test --no-fail-fast --package linutil_core, and ShellCheck on changed scripts.

    Watch out. Config auto_execute resolves entries by display name, so renaming breaks existing configs. multi_select = false on a parent applies to all its children; use it for destructive, interactive or rebooting entries. Preconditions only hide an entry, so scripts must still validate their own requirements.

    About

    This is the Linutil menu map, published with GitHub Pages from the map-util repository. The repository is also the development environment: it holds the generator scripts that build these pages from Linutil's core/tabs/*/tab_data.toml, and the diagram-design skill used for the diagrams.
